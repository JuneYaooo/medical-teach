# R5 写作润色与审稿回复 — 录制规格

## 基本信息

| 项目 | 内容 |
| --- | --- |
| 输出文件 | `WorkBuddy教程/录屏/R5-WorkBuddy实操.mp4`（及同名 .json、.vtt） |
| 目标时长 | 3 分 00 秒 – 3 分 45 秒 |
| 前置产物 | `$WS/演示输出/R4/`（缺失时按 README 3.3 从参考结果复制） |
| 用到的素材 | `实操素材/虚构审稿意见.md`、`演示输出/R4/结果表.md` |
| 这一段要教会 | ① 回复审稿意见要先分类、先定立场，再动笔；② 不合理的要求（事后挑显著亚组）要礼貌拒绝；③ 回复信里每个数字都要能对回结果表；④ 稿件不在手时只能写“拟修改”，不能写“已修改” |

## A. 录前重置

```sh
export WS=~/WorkBuddy录制/WorkBuddy教程
test -d "$WS/演示输出/R4" || cp -R "$WS/参考结果/R4" "$WS/演示输出/R4"
rm -rf "$WS/演示输出/R5"
mkdir -p 录屏重录方案/_work/R5/raw
```

在 WorkBuddy 里：关闭右侧预览区所有标签页；左侧任务列表清空或收起；确认模型为统一模型（README 3.4）。

## B. 录制步骤

### S1 看一眼审稿意见（原始片段 `R5-S1.mp4`）

1. 开始录制，画面在 WorkBuddy 首页。
2. 在 Finder 打开 `~/WorkBuddy录制/WorkBuddy教程/实操素材/`，双击 `虚构审稿意见.md`，用“文本编辑”或任一 Markdown 预览打开，窗口调成 1440×900。
3. 停在文件开头 3 秒，让 8 条意见尽量完整出现在画面里（放不下就慢慢滚动一次）。**标记 M1-1**。
4. 滚动到第 6 条意见（要求新增 5 个亚组并突出显著结果的那条），停 3 秒。**标记 M1-2**。
5. 关闭窗口，结束录制。

### S2 先分类、定立场（原始片段 `R5-S2.mp4`）

1. 开始录制。
2. 点左上角“新建任务”（对话气泡加号图标）。确认输入框下方显示 `WorkBuddy教程`。
3. 点击输入框，粘贴（**原样，不改一字**）：

```text
当前工作空间：WorkBuddy教程。
请结合实操素材/虚构审稿意见.md和演示输出/R4/的分析结果，整理全部审稿意见，按方法、统计、解释和写作分类。逐条列出问题、证据、建议立场、需要修改的位置及尚未完成的工作，保存审稿意见处理表到演示输出/R5/，由我确认回复立场后继续撰写。
```

4. 停 3 秒。**标记 M2-1**。
5. 点发送。等待生成完成（README 4.3）。回复里出现立场表文件卡片（文件名类似 `R5-立场表.md`）时 **标记 M2-2**。
6. 点击立场表文件卡片，右侧预览打开。滚动到“一页速览”或逐条汇总表，停 5 秒。**标记 M2-3**。
7. 在表里找到第 6 条（C6）那一行，停 4 秒。**标记 M2-4**。
8. 找到第 4 条（C4，缺失数据处理）那一行，停 4 秒。**标记 M2-5**。
9. 结束录制。

### S3 给出立场并撰写（原始片段 `R5-S3.mp4`）

1. 开始录制。
2. 点击同一任务的输入框，粘贴：

```text
当前工作空间：WorkBuddy教程。
我的回复立场：接受第1–5、7、8条；第6条说明不进行事后亚组显著性筛选。请完成现有材料支持的修改，撰写完整英文Results和逐条回复信；每个数字对应来源表或单元格，未完成的分析不能写成已经完成。修改位置使用章节和段落。交付Results、回复信、术语表、修改前后对照和数字核对表，并导出可编辑Word文档，保存到演示输出/R5/。如保留修订标记，核实Word文件确实包含修订。
```

3. 停 3 秒。**标记 M3-1**。
4. 发送，等待生成完成。回复里出现多个文件卡片时 **标记 M3-2**。
5. 结束录制。

**此时按“C. 分支”判断走主线还是分支 B。**

### S4 纠正“已完成”说法（仅主线，原始片段 `R5-S4.mp4`）

1. 开始录制。
2. 先点击回复信文件卡片（文件名含“回复信”），滚动到 C1 分支检查里找到的那句“已完成”说法，停 4 秒。**标记 M4-1**。
3. 点击输入框，粘贴：

```text
请逐条检查回复信和Results段落：稿件本体不在工作区，任何“we have added / we have revised / we have removed / 已修改 / 已补充”这类已完成表述，一律改成 Proposed response / Proposed change 的拟稿写法；缺失数据敏感性分析没有做，写成待完成，不能用HC3结果代替；没有固定分页，位置一律写章节和段落，不写页码。改完后把每个数字再对照演示输出/R4/结果表.md核对一遍，更新交叉核对表。
```

4. 停 3 秒。**标记 M4-2**。
5. 发送，等待完成。点击更新后的回复信文件卡片，滚动到刚才那一处，停 5 秒。**标记 M4-3**。
6. 结束录制。

### S5 核对数字和拒绝的写法（原始片段 `R5-S5.mp4`）

1. 开始录制。
2. 点击文件卡片打开交叉核对表（文件名含“交叉核对”），找到 −5.60 那一行（主要结果的调整均数差），停 4 秒。**标记 M5-1**。
3. 在右侧预览区上方点“+”打开新标签页，点“查看工作空间”，依次点开 `演示输出` → `R4` → `结果表.md`，滚到“主要结果”表，停 4 秒。**标记 M5-2**。（R4 的文件不是本任务的产物，不会出现在“查看所有产物”里。）
4. 打开回复信文件，滚到文件开头，停 3 秒（能看到 Proposed response 的说明）。**标记 M5-3**。
5. 滚到 Comment 6 的回复段，停 5 秒。**标记 M5-4**。
6. 结束录制。

## C. 分支

S3 结束后，检查 `$WS/演示输出/R5/` 下文件名含“回复信”的文件和含“Results”的文件：

```sh
grep -n -i -E "we have (added|revised|removed|performed)|has been (added|revised)|已修改|已补充|已完成修改|page [0-9]|p\. ?[0-9]|第 ?[0-9]+ ?页" "$WS/演示输出/R5/"*回复信*.md "$WS/演示输出/R5/"*Results*.md
```

- 有命中（写成了已完成，或编了页码）→ **主线**，录 S4。镜头 9–10 用主线版本。
- 没有命中 → **分支 B**，跳过 S4，镜头 9–10 换成下面的分支 B 镜头。
- 另外检查立场表里 C6 那一行是否含“不接受 / 不照做 / 拒绝 / 不做”。不含的话，这是别的错误：照实录下来，在 report.md 写明，并在 S4 的纠正指令末尾追加一句“第6条的立场是礼貌拒绝事后亚组筛选，请改正立场表和回复信。”

数字以实际生成为准：如果 R4 结果表里的均数差、置信区间、分析人数和下文旁白不同，旁白改成实际值，并在 report.md 列出。
