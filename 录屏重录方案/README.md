# 录屏重录方案（执行规格）

本文件夹是给执行者（Codex 或人）的**录制规格**。照着做，就能重新录出 19 段带讲解旁白和字幕的教学录屏。

- `README.md`（本文件）：所有课通用的环境、录制方法、剪辑方法、交付标准。**先完整读完本文件。**
- `00.md`、`01.md`、`R1.md`…`R8.md`、`P1.md`…`P9.md`：每段录屏的具体规格，包括每一步点哪里、输入什么文字、等什么、剪成什么样、旁白逐字稿。

每课文件里，**代码块中的文字就是要原样粘贴的输入，一个字都不要改**。旁白逐字稿就是字幕和配音的原文。

---

## 一、为什么重录（背景）

旧录屏能播放，画面也清晰，但学员看不懂，原因有五个：

1. 没有声音，也没有讲解，字幕只有章节名。
2. 大部分时间在滚动整屏文字，网页里视频较小，字看不清；关键数字和关键句没有放大，也没有圈出。
3. 每课最重要的“发现错误 → 纠正”没拍清楚（例如 R7 只录了结果；R4 有一个章节只有 1.3 秒）。
4. 画面混入无关内容：其他课的标签页、无关会话、系统弹窗，前后模型也不一致。
5. 网站写“1 分钟录屏”，实际时长 12 秒到 2 分 25 秒不等。

新录屏要解决这五点：**每段有旁白和字幕，关键处放大并标框，完整呈现纠错过程，画面干净。**

## 三、录制环境（每次开录前检查）

### 3.1 机器与软件

- macOS，WorkBuddy **5.9.0**（课程按此版本编写；如果版本不同，在 report.md 里记录版本号和界面差异）。
- ffmpeg（`/opt/homebrew/bin/ffmpeg`）、Python 3。
- 中文配音使用 macOS 自带 `say -v Tingting`。
- 字体：`/System/Library/Fonts/PingFang.ttc`（字幕、标题卡用）。

### 3.2 录制专用工作区（重要）

**不要在仓库里的 `WorkBuddy教程/` 文件夹里录制**，否则会覆盖仓库的参考结果。使用练习包解压出来的干净副本：

```sh
mkdir -p ~/WorkBuddy录制
cd ~/WorkBuddy录制
rm -rf WorkBuddy教程
unzip -q /Users/june2/code/github/medical-teach/WorkBuddy教程/WorkBuddy教程-练习包.zip
ls WorkBuddy教程   # 应看到：实操素材  演示输出  参考结果  开始前请读.txt
```

下文中的“工作区”都指 `~/WorkBuddy录制/WorkBuddy教程`，记为 `$WS`：

```sh
export WS=~/WorkBuddy录制/WorkBuddy教程
```

### 3.3 录制顺序与课间依赖

按以下顺序录，后面的课会用到前面课的产物：

`01 → R1 → R2 → R3 → R4 → R5 → R6 → R7 → R8 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8 → P9 → 00`

| 本课 | 需要的前置产物 | 如果缺失 |
| --- | --- | --- |
| R5 | `$WS/演示输出/R4/` | `cp -R "$WS/参考结果/R4" "$WS/演示输出/R4"` |
| R6 | `$WS/演示输出/R3/` | `cp -R "$WS/参考结果/R3" "$WS/演示输出/R3"` |
| R8 | `$WS/演示输出/R5/` | `cp -R "$WS/参考结果/R5" "$WS/演示输出/R5"` |

每课开录前，按该课文件“A. 录前重置”执行，清空本课的输出文件夹，确保画面里是**当场新生成**的文件。

### 3.4 WorkBuddy 界面状态

- 窗口大小 **1440×900**，放在主屏幕左上角（x=0, y=25）。其余窗口全部最小化或隐藏。
- 若 WorkBuddy 支持 `Cmd+=` 放大界面，放大一级（125%）；不支持就保持默认，靠后期放大。
- **左侧任务列表**：录制前把历史任务归档或删除，只留本课任务。做不到的话，录制时把左侧栏收起（点左上角侧栏按钮）。
- **右侧预览区标签页**：开录前关闭所有标签页。
- **模型**：输入框右下角“快速”菜单里，19 段统一选同一个模型（建议 GLM-5.3-Flash）。在 report.md 里写明。
- **权限**：输入框下方“默认权限”保持默认。
- **工作空间**：每个新任务都确认输入框下方显示 `WorkBuddy教程`（选择方法见 01.md 的 S1）。

### 3.5 系统状态

- 打开“勿扰模式”，关闭所有通知。
- 提前在“系统设置 → 隐私与安全性”给 WorkBuddy 授予文件和文件夹、麦克风等权限，避免录制中弹窗。
- 隐藏桌面图标；菜单栏不要显示个人信息。
- 浏览器（00、R1、R2 课会用到）使用干净的窗口，不要露出书签栏和其他标签页。

## 四、录制方法

### 4.1 原始素材：每个步骤录一段

每课文件“B. 录制步骤”里有 S1、S2…… 每一步录成一个原始片段：

```sh
mkdir -p 录屏重录方案/_work/<课号>/raw
# 查看屏幕设备编号
ffmpeg -f avfoundation -list_devices true -i "" 2>&1 | grep -i "capture screen"
# 录制（把 1 换成主屏幕的编号），按 q 或发送 SIGINT 结束
ffmpeg -f avfoundation -capture_cursor 1 -capture_mouse_clicks 1 -framerate 30 \
  -i "1:none" -c:v libx264 -preset ultrafast -crf 18 -pix_fmt yuv420p \
  录屏重录方案/_work/<课号>/raw/<课号>-S<n>.mp4
```

- 不录声音（配音在后期加）。P6 的试听音频在后期直接混入音频文件，不要录系统声音。
- 录制全屏，后期再裁到 WorkBuddy 窗口（Retina 屏要注意坐标是 2 倍像素，裁剪前先用 `ffprobe` 确认分辨率）。

### 4.2 标记关键时刻

每个步骤里写了 **标记**（例如 `M1-2 文件卡出现`）。操作到这一刻时，记下它在当前原始片段里的秒数，写入 `_work/<课号>/marks.json`：

```json
{ "S1": { "M1-1": 3.2, "M1-2": 8.9 }, "S2": { "M2-1": 1.5 } }
```

剪辑时按标记取画面，所以标记要准（误差 0.5 秒以内）。

### 4.3 操作规范

- **输入文字一律用粘贴**：先把代码块里的文字写入剪贴板（`pbcopy`），点击输入框，`Cmd+V`。粘贴后**停 3 秒**再发送，留出放大展示的画面。
- 发送：点输入框右下角的黑色圆形箭头按钮，或按回车。
- **等待生成完成**的判断：回复下方出现“共消耗 …”那一行，且输入框右下角的按钮从停止状态变回箭头。单次等待超过 15 分钟视为失败。
- 生成失败或报错：新建任务，重新粘贴同一段文字，重录这一步，并在 report.md 记录。
- **鼠标**：移动要慢（每次移动 0.4 秒以上），不要在画面上乱晃；不操作时把鼠标移到不遮挡内容的空白处。
- **滚动**：每次最多滚半屏，滚到要讲的内容后停 3 秒。
- **打开文件预览**：点击回复里的文件卡片，文件会在右侧预览区打开。需要打开没有文件卡片的文件时，点“查看所有产物”，或在工作区文件列表里点击。
- Excel/CSV 需要看单元格公式时，用系统默认的表格软件（Numbers 或 Excel）打开，窗口同样调成 1440×900。
- 画面里一旦出现弹窗、无关会话、其他课的标签页，这一步**重录**。

## 五、剪辑方法

每课文件“D. 剪辑表”逐个镜头规定了画面来源、画面处理和旁白。按以下通用规则执行。

### 5.1 配音

1. 旁白逐字稿先按第六节“读音替换表”替换成朗读稿（只用于配音，字幕仍用原文）。
2. 生成配音：

```sh
say -v Tingting -r 185 -o shot.aiff "朗读稿"
ffmpeg -i shot.aiff -ar 48000 -ac 2 shot.wav
```

3. 每个镜头时长 = max(配音时长 + 0.6 秒, 剪辑表里写的“最短时长”)。
4. 画面比配音短：最后一帧定格补齐（`tpad=stop_mode=clone`）。画面比配音长：等待类画面加速（最高 16 倍），其他画面截掉多余部分，不要加速正常操作。

### 5.2 画面处理词汇表

剪辑表的“画面处理”一栏只使用下面这些说法：

| 写法 | 做法 |
| --- | --- |
| **全窗口** | 裁到 WorkBuddy 窗口，等比缩放到 1920×1080，空白处填 `#F5F5F7` |
| **放大：左栏** / **放大：右栏** | 只保留窗口左半（对话区）或右半（预览区），放大到画面高度 |
| **放大：输入框** | 裁出输入框区域，放大到画面宽度的 80% 居中 |
| **放大：「关键词」** | 用 OCR 找到这段文字所在位置，以它为中心裁出约 1/3 窗口大小的区域放大；用 0.5 秒平滑推近（zoompan） |
| **红框：「关键词」** | 在这段文字外围画框，外扩 8px，线宽 6px，颜色 `#E5484D`（错误） |
| **绿框：「关键词」** | 同上，颜色 `#30A46C`（正确 / 改后） |
| **黄框：「关键词」** | 同上，颜色 `#F5A524`（注意 / 部分通过） |
| **并排：A ｜ B** | 两个画面各缩放到 940×1000 左右，左右排列（hstack），中间 20px 间隔，上方各加一个小标题 |
| **加速 ×N** | `setpts=PTS/N`，右上角加角标“实际等待 X 分 Y 秒 · 已加速” |
| **标题卡** | 1920×1080 纯色 `#1F2A44` 背景，白色 PingFang 大字（主标题 72px，副标题 40px） |
| **字卡** | 同标题卡样式，列 2–3 行要点，每行前加 ①②③ |
| **角标：文字** | 右上角圆角色块 + 白字，36px |

**OCR 定位**：用 macOS Vision 框架写一个小脚本（Swift 或 Python + pyobjc），输入一帧截图和关键词，输出文字的外框坐标。找不到关键词时，在 report.md 记录，改用人工指定坐标。

### 5.3 字幕

- 每个镜头的旁白逐字稿就是字幕原文。超过 22 个字时按标点切成多行（每条字幕最多 2 行、每行最多 22 字），时间按字数比例分配到该镜头的配音时长内。
- 字幕**烧进画面**（硬字幕）：底部居中，白字 44px，黑色半透明底（透明度 60%），距底边 60px。
- 同时输出同内容的 `.vtt` 文件。
- 标题卡和字卡如果有旁白，也加字幕。

### 5.4 合成与导出

- 镜头之间直接切换，不加转场；章节之间可加 0.3 秒淡入淡出。
- 背景音乐：不加。
- 导出：

```sh
ffmpeg -i edit.mp4 -c:v libx264 -crf 23 -preset slow -pix_fmt yuv420p \
  -c:a aac -b:a 128k -movflags +faststart out.mp4
```

- 文件大小控制在 60MB 以内（GitHub 单文件上限 100MB）。超过就把 crf 调到 26。

## 八、Agent 输出和预期不一样时

每课的纠错环节，是按上次实操**真实出现过**的错误设计的。重录时 WorkBuddy 不一定再犯同样的错误。每课文件“C. 分支”写了判断方法：

- **出现了预期错误** → 走主线：录纠正指令和改后结果。
- **没有出现预期错误** → 走分支 B：不发送纠正指令，改用分支 B 的旁白（“这次它写对了，但这里最容易出错……”），画面放大展示它写对的地方。**绝对不要为了配合脚本去诱导或伪造错误。**
- **出现了别的明显错误** → 照实录下来，在 report.md 写明，录制完成后由人决定是否补纠正。

数字类结果（样本量、均数差、频次等）和脚本里写的不一致时，**以实际生成的为准**，把旁白和字幕里的数字改成实际值，并在 report.md 列出差异。

## 十一、整体验收

- [ ] 19 段都有音轨（`ffprobe` 能看到 audio 流），时长 1 分 30 秒到 4 分钟。
- [ ] 每段抽 12 帧拼图检查：没有其他课的标签页、无关会话、系统弹窗。
- [ ] 每段至少 3 处放大，纠错环节有红框 / 绿框对比（走分支 B 的除外）。
- [ ] 字幕与配音一致，没有读错的术语。
- [ ] 19 段使用同一个模型。
