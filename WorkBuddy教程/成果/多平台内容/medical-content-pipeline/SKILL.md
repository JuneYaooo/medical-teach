# medical-content-pipeline（医学内容流水线）

## 铁律（任何一步不得绕过）

1. **缺事实卡，先索取。** 用户未提供事实卡（CSV，含编号/事实陈述/来源/适用与限定/核对状态/医生签署列）时，必须先向用户索取，并说明理由。**禁止凭记忆、模型知识或"常识"补写医学事实。** 来源缺失时同样先索要，不自行检索代拟事实卡。
2. **交付完整正文与独立核对稿。** 正文采用自然可读的成稿形式；口播正文与TTS纯文本只保留实际朗读内容。事实编号、制作参数、来源及审核记录分别放在核对稿、制作稿和审核记录中。
3. **如实记录审核状态。** 来源核对不等于临床医生审核，不把未签署记录写成已审核。缺少医生签署时仍完成用户请求的内容文件，在独立审核记录中写明实际状态及待办。只有真实授权才能执行发布，生成内容不等于已发布。
4. **在核对稿中逐句映射 F 编号。** 每个医学判断、数字、因果、效果暗示与限定均需检查，不能因其是开场、过渡或修辞而豁免。事实卡不支持时删改或补充可核实来源；不要用无关编号装饰句子。
5. **适用限定必须随事实走。** 事实卡"适用与限定"列的每个限定条件，在使用该事实的载体中必须保留（逐字或同义不弱化）。发现丢失要修复并在对照表中登记。
6. **不新增事实卡之外的医学信息。** 数字、单位、切点、频次只能来自事实卡；受众定位、制作参数等非医学数字须显式标注。

## 工作流程

### 第 1 步：索取与校验事实卡
- 读取事实卡 CSV，检查列是否齐全、编号是否唯一。
- （可选，若有网络且用户同意）对来源页面做来源核查，逐条记录"来源是否支持"，写入校验记录。抽查结论仍属来源核对。
- 输出校验记录：两种核对类型的状态表 + 各卡"适用与限定"清单。

### 第 2 步：生成多载体内容
按用户需要生成载体（如：短文、30秒脚本、6页图文方案、60秒口播）。每个载体：
- 完整可读稿（不是提纲）；
- 独立核对稿中的医学信息对应 F 编号；
- 适用限定随句保留；
- 来源与审核状态独立记录；
- 时长/篇幅导致的覆盖取舍要显式声明（哪些事实未用、为什么）；
- 有声/口播载体须**实测字数**（去标点、去编号后计），按目标语速换算时长并标注"预估、未录音实测"；超出可读区间就压缩，而不是标注"约60秒"了事。

### 第 3 步：事实×载体对照表
以**实际句子**为准逐格核对（摘录原句，不得以"有编号"代替语义核对），包含四部分：
1. 事实×载体覆盖矩阵（原句摘录 + 未用事实说明）；
2. 限定词保留核对（逐卡）；
3. 新增数字检查（逐文件扫描，逐个判定来源）；
4. 未编号医学句检查（逐文件人工通读，逐条登记判定）。

### 第 4 步：编号检查脚本（辅助，只查编号）
运行 `scripts/check_fnumbers.py`（仅 Python 标准库，仅在指定文件内读写，不联网）：

```bash
python3 scripts/check_fnumbers.py --factcard 事实卡.csv --input 载体1.md 载体2.md --report 报告.md
```

**脚本能力边界（必须向用户说明）：**
- ✅ 能查：事实卡是否存在、医生签署状态、[Fxx] 编号格式、引用了不存在的编号、每卡被引次数、从未被引用的卡。
- ❌ 不能查：句子是否是医学论断（检测不出"未编号的医学句"）、限定词是否丢失、数字与单位是否正确、编号与句子语义是否匹配。
- 这些"不能查"的项必须由人工按第 3 步对照表完成。脚本通过 ≠ 内容正确。

## 退出条件

- 用户要求的载体完整，核对稿中每句医学信息有对应依据；
- 对照表四部分完成，发现项已修复或登记；
- 脚本编号检查通过（或差异已解释）；
- 发布前核实真实审核状态与用户发布授权；卡片字段或脚本通过不构成发布批准。

## 模板使用说明

1. **接需求**：用 `templates/输入模板.md` 收集主题、事实卡路径、载体清单、共同核心事实、输出目录。缺事实卡或缺来源→按铁律1先索取/补资料，不得开工。
2. **选载体模板**：按载体清单取对应 `载体模板-*.md`；每个载体产出两件——可阅读正文（不带F编号）＋独立核对稿（带[Fxx]逐句映射）。口播类另出 TTS 纯文本（与正文逐字一致，只含朗读文字），并实测去标点字数换算时长。
3. **共同核心**：用户指定的核心事实（如 F05/F08/F09）必须出现在所有载体；短载体放不下的其他卡，在"覆盖取舍"显式声明并在对照表登记差异。
4. **核对**：先人工完成对照表四项（覆盖矩阵/限定保留/新增数字/未编号医学句），发现即修复四份内容并复测；再跑 `check_fnumbers.py` 做编号层复查。**脚本通过 ≠ 语义通过**。
5. **审核记录**：独立成档，如实写"来源核对完成 / 医生签署未完成"；未签署稿可交付但不可发布。
6. **完整范例**：见项目 `家庭血压项目/成果/多平台内容/`（2026-11-02 实跑：家庭血压测量准备，四载体＋对照表＋审核记录，含3处限定修复记录）。
