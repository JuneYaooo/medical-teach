# My Health Content — 健康科普创作与审查

## 目标

为面向普通患者的健康科普内容提供固定工作流：**事实卡核对 → 内容完成 → 语义核验 → 发布前检查**。产出两类分离的交付物：读者可读的**正文**（只保留读者需要的内容），以及内部核对文档（修改对照、审核状态）。审核状态如实记录，**不得冒称医生签署**。

## 触发边界（先判断，再动手）

本技能只处理**面向患者/公众的健康科普创作与审查**。以下情况**不进入本流程**：

- 普通通知、会议纪要、行政文案等**非健康类内容** → 直接按常规方式处理，完整交付，不做医学核对。
- 个体诊疗建议、处方问题、临床研究方案 → 提示超出科普范围，建议咨询医疗专业人员或使用对应专业流程。
- 判断存疑时，先向用户说明归类理由，再继续。

**禁止行为**：不得因内容含医学词汇就触发完整医学流程；不得对正常内容无中生有地报问题；不得跳过核对直接交付声称"已审核"的稿件。

## 工作流

### 第一步：核对事实卡（先于一切写作）

1. 读取用户提供的事实卡（如 `家庭血压事实卡.csv`）。确认其结构包含：编号、事实陈述、来源、适用与限定、核对状态、医生签署、核对日期。
2. 逐条检查事实卡可用性：
   - 核对状态不是"来源核对"的条目 → 只能以"待核对"标注引用，不得当作已验证事实。
   - **医生签署为"未签署"的条目 → 照常使用。"未经医生签署""待医生签署"等审核状态只写入核对稿与独立审核记录，绝不写入正文；正文只保留读者友好的来源行（如事实卡允许），不含任何内部流程状态（核对状态、签署状态、编号等）。任何输出中禁止出现"医生审核通过""医学签发"等不实表述。**
   - 事实卡为空或缺失 → 停止写作，向用户说明并请求事实卡或可核来源。
3. 稿件中每一条医学论断都必须映射到事实卡编号；映射不到的按"无来源"处理（见拦截规则）。

### 第二步：完成内容

按 `references/风格规范.md` 写作（面向普通患者：用"您"，短句，少术语）。初稿完成后立即进入第三步，不要边写边自我确认。

### 第三步：语义核验

逐句检查，按 `references/检查清单.md` 执行。**五类拦截项**（命中任何一项必须改写或删除，并在核对稿中记录依据）：

| # | 拦截类型 | 判定标准 | 处理 |
|---|---------|---------|------|
| 1 | 无来源断言 | 论断在事实卡中无对应编号 | 改写为事实卡内容，或删除，或标注"待核对" |
| 2 | 效果保证 | "保证/根治/治愈/百分百/彻底"等绝对化承诺，包括对测量准确性、有效性的保证（如"保证读数准确"） | 改写为事实卡支持的中性操作表述 |
| 3 | 自行调药 | 建议读者自行停药、换药、加减剂量 | 改为"与医生/医疗人员讨论后再调整" |
| 4 | 个人信息 | 出现真实姓名、身份证号、电话、病历细节等 | 删除或匿名化 |
| 5 | 不当人群外推 | 把一般结论强加给儿童、孕妇、特殊人群，或声称"所有人适用、无需评估" | 限定适用人群；特殊人群注明"需医生评估" |

**语义判定要求（核验是语义判断，不是关键词匹配）**：

- 逐句判断句子的**完整含义**是否被来源支持，而非只看是否含敏感词；也不因"不是治疗承诺"而放过保证类表述——对准确性、有效性的保证同样属于承诺，需要来源支持其完整含义（如"保证读数准确"是测量准确性保证，事实卡只写测前 30 分钟避免吸烟、咖啡因和运动，不支持"保证"级含义，必须改为中性操作说明）。
- 论断映射到事实卡编号只证明**编号正确**，不等于**语义正确**；映射后仍须核对句子完整含义与事实陈述、适用与限定一致。
- 误报防护：与医学断言无关、不构成任何效果或准确性承诺的普通修辞不拦截；但句子只要做出了效果或准确性层面的承诺，即属于拦截项，无论用词。
- 只有稿件文本真实命中上述标准才算问题，不得对正常内容无中生有地报问题。

### 第四步：发布前检查

1. 逐项过 `references/检查清单.md` 的发布前检查表，全部通过才交付。
2. 交付物分两份：
   - **正文**：读者视角，只保留读者需要的内容。不含编号、来源位置、核对状态等内部信息（可用"来源：美国心脏协会官网"这类读者友好的来源行，如事实卡允许）。
   - **核对稿**：修改对照表（原文 → 修改后 → 问题类型 → 依据事实卡编号），外加**审核状态页**（单独记录：核对状态、医生签署状态、核对日期、遗留风险）。
3. 正文与核对稿不得混在同一文件里。

## 输入与输出模板

- 输入要求与格式：`assets/输入模板.md`
- 正文输出：`assets/输出模板-正文.md`
- 核对稿输出：`assets/输出模板-核对稿.md`

## 使用示例

**示例 A（审查）**：用户提供待审稿 + 事实卡 → 走完整四步 → 交付修订正文 + 核对稿（含修改对照与审核状态）。

**示例 B（创作）**：用户给主题 + 事实卡 → 先映射可用条目，再写作，再核验、检查 → 交付正文 + 核对稿（标明"本次无修改，全部论断映射到 Fxx"）。

**示例 C（非健康内容）**：用户发来会议通知请求整理 → 判定为非健康类 → 不进入本流程，直接常规处理交付，并在回复中说明归类。
