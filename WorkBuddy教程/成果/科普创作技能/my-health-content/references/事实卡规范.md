# 事实卡规范 — 结构、可用性与使用方式

## 1. 事实卡的标准结构（CSV）

| 列名 | 必填 | 说明 |
|------|------|------|
| 编号 | 是 | 唯一 ID，如 F01；正文核对映射用 |
| 事实陈述 | 是 | 一条一个事实，不含修饰与承诺 |
| 来源 | 是 | 可验证 URL 或文献标识 |
| 来源位置 | 是 | 来源内的具体章节/标题 |
| 适用与限定 | 是 | 适用人群/场景与不适用情况 |
| 核对状态 | 是 | "来源核对"= 已对来源核实；其他值视为未核实 |
| 医生签署 | 是 | "已签署"/"未签署" |
| 核对日期 | 是 | YYYY-MM-DD |

## 2. 可用性判定

- **可用**：核对状态 = 来源核对。可用于正文，无论医生签署与否。
- **受限可用**：医生签署 = 未签署 → 可以使用，但审核状态页必须写明"未经医生签署"；禁止在任何输出中出现"医生审核/签发/背书"。
- **不可用**：核对状态非"来源核对" → 只能以"待核对"出现，不得作为正文论断基础。

## 3. 映射规则

- 稿件每个医学论断 → 恰好映射一个事实卡编号；写入核对稿的"依据"列。
- 一句话包含多个论断时拆开分别映射。
- 事实卡"适用与限定"列写明的限制必须反映到正文（如"特殊人群需额外确认"→ 正文写"特殊人群请先咨询医生"）。
- 映射不到 → 触发"无来源断言"拦截（见 SKILL.md 第三步）。

## 4. 引用完整性

- 不得改写事实陈述的数值、条件、限定。
- 不得把"适用与限定"中的例外情形写成普遍结论（这同时属于"不当人群外推"）。
- 事实卡之间冲突时：两条都不用于正文，在核对稿记录冲突并请用户裁决。

## 5. 事实卡本身的维护

- 新增条目按上表补全所有列。
- 核对状态与医生签署只能由人工核实/签署流程更新；AI 不得代填"已核对""已签署"。
