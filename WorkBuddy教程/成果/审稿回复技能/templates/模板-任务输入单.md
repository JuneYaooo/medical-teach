# 模板：任务输入单（把审稿回复任务交给技能时填）

> 目的：一次给全，避免技能在缺信息时靠猜。缺哪项就如实写"未提供"，技能会按对应规则降级处理。

```markdown
# R{n} 审稿回复任务输入单

## 1. 审稿意见原文
（逐条照抄，不改写。多条要求混在一条里的也原样给。）

## 2. 作者立场（如已定）
- C1：接受 / 部分接受 / 不接受实质要求 / 需先补证据
- C2：（未定 → 技能停在拆分表，等待逐条给立场）

## 3. 稿件状态（三选一，必填）
- [ ] 原稿文件在本工作区：路径 ______（改动核对后可标 APPLIED）
- [ ] 原稿未提供，仅写新拟稿（全部 PROPOSED，位置用章节/段落）
- [ ] 已合并部分修改：已合并清单 ______（引用既有记录，不改写为技能产出）

## 4. 分页状态
- [ ] 有固定分页（可给页码/行号）
- [ ] 无固定分页 → 位置一律 Section + paragraph，回复信卷首加未分页声明，不编页码

## 5. 证据底稿
（文件清单 + 版本/日期，例如：成果/数据分析/完整分析报告.md 2026-11-01）
- 没有 → 相关条目证据状态记 U，回复留空并索取

## 6. 语言
- 回复信语言：____（未指定则沿用稿件语言；同信不混语种）

## 7. 特别约束（可选）
（例如：某条不做实质修改；不作样本量断言；数据为合成数据需加声明等）
```

**技能收到输入单后的第一动作**：核对第 2 项——立场未全 → 只产出意见拆分表并以 AWAITING STANCE 结尾；立场已全 → 按四阶段推进。
