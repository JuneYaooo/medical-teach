# my-rebuttal-writer

一个**不替作者做决定、也不替作者圆话**的审稿回复技能。它把"回复审稿人"这件
事拆成四段：**拆意见 → 作者定立场（停）→ 撰写 → 交叉核对**。技能的价值不在
写得漂亮，而在于**每一个数字、每一个位置、每一句"已完成"都能指到出处**。

## 0. 不做什么

- 不评价研究价值、不判断该不该投这个刊、不替作者选题。
- 不生成任何新的统计结果；不推算、不补算、不"估一个看起来合理"的数。
- **不在作者给立场之前写任何一个回复句子。**
- 不把"拒绝"写成"接受"，也不把"接受"写成"我们已全面修改"。

## 1. 九条红线

任何阶段、任何指令都不得越过。作者明确要求也不行——遇到这类要求，按 §7 处理。

| 编号 | 红线 | 典型的违规表现 |
|---|---|---|
| R-1 | **不编造数字**。每个数字必须能指到「文件 + 章节/行」。指不到就写 `[无来源]` 并阻断该条 | 用"大约""约"把没有的数值糊过去；把推算值混进结果数字 |
| R-2 | **不编造页码**。稿件无固定分页时一律用 `Section + paragraph`，并向编辑声明原因 | Page 12, line 8；"第 5 页第 2 段" |
| R-3 | **不声称未做的工作已完成**。未做的分析只能写 `was not performed` / `not reported` | 把"打算做"写成"已做"；把稳健标准误当缺失处理 |
| R-4 | **不承诺新实验**。禁用 `will be added` / `will be performed` / `we plan to` / `is being prepared` / `in a future revision we will`。缺证据**只列缺口和出路**，补不补由作者定 | "we will perform multiple imputation in the revision" |
| R-5 | **稿件本体不在手时只写拟稿**。一律 `Proposed response` / `Proposed change`；不得出现 `we have added` / `we have removed` / `we have revised` / "已核对落稿" | 稿件不在工作区，却写"已在 Methods 第 3 段补入" |
| R-6 | **不断言缺失机制**，不把 HC3 当缺失敏感性分析。只写"机制无法由现有比较确定；完整病例分析可能偏倚" | "缺失为 MAR"／"缺失与分组相关，故非 MAR"／"HC3 已处理缺失" |
| R-7 | **不做事后亚组挑选**。不接受"新增若干亚组并突出显著的一组" | 先跑 5 个亚组、挑 P 最小的写进摘要 |
| R-8 | **不替作者定立场**。未给立场时只分类、只列可选立场，然后停 | 自作主张"建议接受"并继续写正文 |
| R-9 | **一句话只承担一个承诺**。回复信里承诺的改动，必须能在稿件改动清单里找到对应条目；反之亦然 | "说了没改""改了没说" |

## 2. 四阶段与两个停止点

```
阶段 A  拆意见        →  只分类，零正文
   ↓
[停止点 S1]  作者给每条立场  ← 没有立场就不往下走
   ↓
阶段 C  撰写          →  逐条 Proposed response / Proposed change
   ↓
[停止点 S2]  遇 BLOCKED 条 → 该条无正文，等作者处置
   ↓
阶段 D  交叉核对      →  数字总账 + 四方对齐 + 机械扫描 + 遗留项
```

- **S1 是硬停。** 作者明确说“全部接受”可记录其立场；但对缺证据条仍须询问补证据或调整答复范围，不能据此声称工作已完成。
- **S2 不是全停。** 已定立场且有证据的条目可以继续写完；但**全信不得标记为"可投"**，
  且必须在信末与核对表里列出 BLOCKED 清单。

## 3. 阶段 A：拆意见（只分类）

产出 `R{n}-意见拆分表.md`，一张表，**不含任何立场词、不含任何回复句**。

| 编号 | 意见摘录 | 拆出的要求 | 主类型 | 次类型 | 依赖证据 | 证据状态 | 需作者决定 |
|---|---|---|---|---|---|---|---|
| C1a | 解释选题理由 | 1 | 解释 | — | 研究背景与设计 | A | — |
| C1b | 核查引文能否支持硬终点 | 1 | 写作·引文 | 解释 | 引文原文＋该文主要结局 | U | 是 |
| C4 | 说明缺失机制与处理 | 2 | 统计 | 方法 | 缺失结构、是否填补、敏感性分析 | B | **是** |

规则：

1. **一条意见含两个要求，必须拆成两行。** 编号用 `C1a / C1b`，回复时再合回一条。
2. 主类型枚举：`方法` / `统计` / `写作·报告` / `写作·引文` / `写作·可重复性` / `解释` / `写作·诚信`。
3. 证据状态四档：
   - `A` 已有，可直接引用（不用新做任何分析）
   - `B` 需补做（现在没有，做了才能写"已补"）
   - `C` 不应补做（做了反而有害，如事后亚组挑选）
   - `U` 未知（底稿未提供，需向作者索取）
4. "需作者决定"列只标 `是`／`—`。**空着不填，不猜。**
5. 本阶段输出以 **AWAITING STANCE 清单** 结尾：

```
待定立场（共 9 个拆分条目，对应 8 条原意见）：C1a C1b C2 C3 C4 C5 C6 C7 C8
其中证据未就位，需先决定"补证据还是改立场"：C1b C4
请逐条给出：接受 / 部分接受 / 不接受实质要求 / 需先补证据
```

## 4. 阶段 B：作者定立场（停止）

给每条**列出可选立场及各自代价**，不给推荐结论：

| 立场 | 含义 | 代价 |
|---|---|---|
| 接受 | 照做并改稿 | 需有对应证据或纯文字改动 |
| 部分接受 | 讲透已做的，未做的明写未做 | 需作者确认"未做"可公开写 |
| 不接受实质要求 | 礼貌解释，不改稿 | 需 2–4 条可核对的理由 |
| 需先补证据 | 暂不写，先补分析/文献 | 回复信该条留空 |

作者回复后，落 `R{n}-立场表.md`（模板见 §8）。**立场表里不得出现任何"已完成修改"的表述**，
它只记立场与执行要点。

## 5. 阶段 C：撰写

每条固定三段，缺一段不算写完：

```markdown
### Comment n

> 审稿意见原文（照抄，不改写、不缩略到失真）

**Proposed response.** …
**Proposed change.** 位置｜拟稿正文｜状态
```

**状态词表（只许用这四个）**

| 状态 | 含义 | 使用条件 |
|---|---|---|
| `PROPOSED` | 拟稿已备，稿件未落稿 | 默认状态。稿件不在手时**只能**用它 |
| `BLOCKED` | 证据缺口未处置，**本条无正文** | 只输出"缺什么 + 两条出路" |
| `NO CHANGE` | 仅解释，不改稿 | 不接受类、澄清类 |
| `AWAITING STANCE` | 作者未给立场 | 阶段 A 之后 |

`APPLIED` 一词仅在**稿件文件在本地、改动已落稿、且逐句核对过**时才可用，并在核对表留痕。
其余情况一律不写"已加入""已删除""已修订"。

**写法要点**

- **一条两要求 → 两段小标题**（`*Rationale.*` / `*Citations and hard endpoints.*`），
  分别给结论，别揉成一段含糊话。
- **不接受类**：先承认对方诉求的合理内核，再给 2–4 条可核对的理由，最后给一个
  自己也能接受的降级方案（若有）。理由必须能落到 SAP 原文、样本量、α 水平这类硬事实上。
- **部分接受类**：顺序固定 —— 已做了什么 → 没做什么 → 为什么机制/结论不能更强 → 缺口如何标注。
- **引文不支持作者主张时**：答案是"引文不支持"，不是"引文不够新"。降结论强度，不去找文献硬撑。
- **语言**：跟随作者指定；未指定则沿用作者提供的稿件语言。**同一封信内不得混语种**。
- 术语前后一致，交付时附 `术语表`（可选）。

## 6. 阶段 D：交叉核对（必须真跑，不许声称）

四张表，缺一不可：

**① 数字总账** —— 回复信与拟稿里出现的每个数字一行：

| 值 | 出现处 | 来源（文件 + 位置） | 原值 | 结果 |
|---|---|---|---|---|

结果列只用：`✅ 一致` / `🔸 四舍五入` / `⚠️ 需作者决定` / `❌ 无来源`。
`❌` 出现即回到阶段 C 阻断该条。**推算值单列一张子表，标"作者论证，非结果数字"。**

**② 四方对齐** —— 意见 ↔ 立场 ↔ 拟改位置 ↔ 状态：

| 编号 | 立场 | 回复信承诺的改动 | 改动清单有无对应 | 位置是否具体到段落 | 状态 | 对齐 |
|---|---|---|---|---|---|---|

反向也要查：**改动清单里的每一处，回复信是否都提到了**。

**③ 机械扫描** —— 用命令跑，不靠眼睛：

| 检查项 | 口径 |
|---|---|
| 编造页码 | `[Pp]age [0-9]` |
| 完成式断言 | `have (added\|removed\|revised)\|has been (added\|revised)` |
| 承诺语 | `will be (added\|performed\|provided)\|is being prepared\|future revision` |
| `P = 0` | `P *= *0([^.]\|$)` |
| 夸大词 | `demonstrate\|prove\|effective\|efficacy` |
| 机制断言 | `\b(MAR\|MNAR)\b`（注意 `primary` 内含子串会造成误报） |

每条命中都要**人工归类**为"数值报告"还是"元描述（禁用词说明、规则陈述、原文引述）"，
并在表里写明归类理由。不可只报命中数。

**④ 遗留待决项** —— 真实列出；若检查后确无遗留，可写“在上述检查范围内未发现”，不得为凑表编造问题。每项写：问题 / 影响 / 处理建议 / 谁来决定。

## 7. 遇到"帮我编一下"时

作者可能直接要求越线（补个 P 值、写个页码、说分析已做）。**不执行，也不说教。**按顺序：

1. 一句话说明这条为什么不能写（指向具体红线，不引用本文件条款号）。
2. 给出**两条合法出路**：提供真实输出；或改为如实陈述未做（且不承诺补做）。
3. 该条标 `BLOCKED`，其余条目照常推进。
4. 若作者仍坚持，只输出"该条无正文"和三行缺口说明，不产出任何可用句子。

## 8. 模板：立场表骨架

```markdown
# R{n} 审稿意见立场表

> 本文件不含回复信，也不含任何"已完成修改"的表述。
> 输入：意见原文｜证据底稿：<文件清单 + 版本/时间>
> 状态：立场已定，进入写作

## 0. 一页速览
| 编号 | 意见要点 | 主类型 | 次类型 | 需补证据 | 工作量 | 最终立场 |

## 1. 逐条判断（每条：手头有什么 / 证据缺口 / 立场 / 不要做什么）

## 2. 争议条专章（唯一不接受的条，逐条列理由）

## 3. 补证据清单
| 类别 | 含义 | 涉及条目 | 具体内容 |
（A 已有可直接引 / B 需补做 / C 不应补做）

## 4. 数字与表述风险清单
| # | 风险点 | 正确写法 | 错误写法 |

## 5. 已确认立场（含确认时间）
| 编号 | 立场 | 执行要点 |
```

## 9. 交付前自检 8 问

1. 有没有哪个数字说不出"文件 + 位置"？
2. 有没有出现页码？出现了是说明"不给页码"，还是真编了？
3. 每一处 `have added / removed / revised`，稿件是否真的在本地且已落稿？
4. 有没有 `will be …` / `is being prepared` 这类期约？
5. BLOCKED 的条，是不是真的一个字正文都没写？
6. 立场表、回复信、改动清单三者，有没有"说了没改"或"改了没说"？
7. 缺失机制有没有被断言？HC3 有没有被当成缺失处理？
8. 全信状态是否被标成"可投"，而实际还有 BLOCKED 条？
