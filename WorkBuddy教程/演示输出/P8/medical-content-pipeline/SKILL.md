# medical-content-pipeline（医学内容流水线）

## 铁律（任何一步不得绕过）

1. **缺事实卡，先索取。** 用户未提供事实卡（CSV，含编号/事实陈述/来源/适用与限定/核对状态/医生签署列）时，必须先向用户索取，并说明理由。**禁止凭记忆、模型知识或"常识"补写医学事实。** 来源缺失时同样先索要，不自行检索代拟事实卡。
2. **未有医生签署，不得生成发布终稿。** 事实卡"医生签署"列全部为"未签署"（或为空）时，只能产出**教学草稿**，每个文件头部必须标注：`教学草稿｜医生签署：未签署，不得发布`。即使用户要求"发布版""终稿"，也要先说明缺少签署，可交付的只有草稿。
3. **区分两种核对。** "教学来源核对"（把卡片与来源页面比对）≠"临床医生确认"（执业医生签署）。来源核对做得再多，也不改变"未签署=只能草稿"的状态，且不得把未签署卡标为已确认。
4. **每句医学信息带 F 编号。** 载体中每个含医学信息的句子句尾标注对应事实编号，如 `……避免吸烟[F04]`。一句引用多卡时逐一标注。
   **不得以"修辞性引入"为免核对理由**：凡含判断、因果、效果暗示（如"医生都不敢用""问题出在量法上""量对了才算数"）的句子，即使不带编号，也必须删除、改写为中性提问，或补编号（事实卡确有此内容时）。修辞不能豁免核对。修辞性引入句、免责句可不带编号，但必须在对照表"未编号医学句检查"中逐条登记并判定。
5. **适用限定必须随事实走。** 事实卡"适用与限定"列的每个限定条件，在使用该事实的载体中必须保留（逐字或同义不弱化）。发现丢失要修复并在对照表中登记。
6. **不新增事实卡之外的医学信息。** 数字、单位、切点、频次只能来自事实卡；受众定位、制作参数等非医学数字须显式标注。

## 工作流程

### 第 1 步：索取与校验事实卡
- 读取事实卡 CSV，检查列是否齐全、编号是否唯一。
- （可选，若有网络且用户同意）对来源页面做教学来源抽查，逐条记录"来源是否支持"，写入校验记录。抽查结论仍属教学来源核对。
- 输出校验记录：两种核对类型的状态表 + 各卡"适用与限定"清单。

### 第 2 步：生成多载体草稿
按用户需要生成载体（如：短文、30秒脚本、6页图文方案、60秒口播）。每个载体：
- 完整可读稿（不是提纲）；
- 每句医学信息带 F 编号；
- 适用限定随句保留；
- 头部状态标注（见铁律 2）；
- 时长/篇幅导致的覆盖取舍要显式声明（哪些事实未用、为什么）；
- 有声/口播载体须**实测字数**（去标点、去编号后计），按目标语速换算时长并标注"预估、未录音实测"；超出可读区间就压缩，而不是标注"约60秒"了事。

### 第 3 步：事实×载体对照表
以**实际句子**为准逐格核对（摘录原句，不得以"有编号"代替语义核对），包含四部分：
1. 事实×载体覆盖矩阵（原句摘录 + 未用事实说明）；
2. 限定词保留核对（逐卡）；
3. 新增数字检查（逐文件扫描，逐个判定来源）；
4. 未编号医学句检查（逐文件人工通读，逐条登记判定）。

### 第 4 步：编号检查脚本（辅助，只查编号）
运行 `scripts/check_fnumbers.py`（仅 Python 标准库，仅在课程文件内读写，不联网）：

```bash
python3 scripts/check_fnumbers.py --factcard 事实卡.csv --input 载体1.md 载体2.md --report 报告.md
```

**脚本能力边界（必须向用户说明）：**
- ✅ 能查：事实卡是否存在、医生签署状态、[Fxx] 编号格式、引用了不存在的编号、每卡被引次数、从未被引用的卡。
- ❌ 不能查：句子是否是医学论断（检测不出"未编号的医学句"）、限定词是否丢失、数字与单位是否正确、编号与句子语义是否匹配。
- 这些"不能查"的项必须由人工按第 3 步对照表完成。脚本通过 ≠ 内容正确。

## 退出条件

- 四类载体齐备且每句医学信息带编号；
- 对照表四部分完成，发现项已修复或登记；
- 脚本编号检查通过（或差异已解释）；
- **发布终稿的唯一通行证是事实卡医生签署列全部为"已签署"（签署真实性由流程负责，本技能不核验签署真伪）。**
